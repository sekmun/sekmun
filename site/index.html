One engineer, an agent loop, and a backlog that keeps running out.

The sprint: 744 points against a 260-point forecast

Sprint 57 on the Unified product was planned at 260 points. The loop closed 744. Scope was written and fed in while the sprint ran, growing from 260 to 799 points, and work kept landing over both weekends.

Recent sprints have finished with the backlog empty. The bottleneck stopped being engineering and became specification.

How the loop works

The agents write the code. The engineering is in the gates that decide what gets through.

  1. Write the ticket as a contractAcceptance criteria an agent can be tested against, not a description of intent.
  2. Run it through the harnessomp.sh driving Claude and other models, choosing the model per task rather than tying the workflow to one vendor.
  3. Gate on coverageUnit tests run on every change, and coverage can't go down. An agent can't pass by deleting a test.
  4. Check the front endBrowser tests act as the oracle for UI work, so the loop closes without a person clicking through.
  5. Review with a different modelThe model that writes the change doesn't approve it.
  6. Ship to the edgeMerged work deploys to Cloudflare. This page is built and deployed the same way.
